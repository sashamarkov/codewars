<h2><a href=https://www.codewars.com/kata/629e18298f2d21006516e381/train/python target="_blank">How many permutations where indices change by at most 1</a></h2><h3>6 kyu</h3><h2 id="overview">Overview</h2><p>We are going to be studying permutations of <code>n</code> distinct elements - for simplicity we shall use the integers from <code>1</code> to <code>n</code>.</p><p>If we start with the integers <code>1</code> to <code>n</code> in ascending order in a list:</p><p><code>[1, 2, 3, ..., n-2, n-1, n]</code></p><p>then, for a given value of <code>n</code>, how many permutations of this list are there in which each element's index changes by <strong>AT MOST</strong> 1 after the permutation?</p><hr><h2 id="inputs">Inputs</h2><p>You will be given an <code>integer</code>, <code>n</code>, representing the number of distinct elements that we want to permute. </p><p>As mentioned, for definiteness, you can think of the integers from <code>1</code> to <code>n</code> in a starting list given by <code>[1, 2, ..., n]</code></p><p><strong>Performance requirement:</strong> Values from <code>0</code> up to <code>200</code> may be tested.</p><h2 id="output">Output</h2><p>You must return an <code>integer</code> representing the total number of possible permutations of the list <code>[1, 2, ..., n]</code> that satisfy the requirement.</p><h2 id="important-notes">Important notes</h2><ol><li>The identity permutation, where no element changes its index, is a valid permutation according to the definition, so make sure you include it in your total.</li><li>You <strong>cannot</strong> wrap-around the list, so changing element <code>1</code> with element <code>n</code> is <strong>not allowed</strong> (except for the case <code>n = 2</code> of course).</li></ol><hr><h2 id="walk-through-example">Walk-through Example</h2><p>Let's consider the case <code>n = 4</code>; so concretely we are looking at permutations of the list <code>[1,2,3,4]</code></p><p>There are in total <code>n! = 4! = 24</code> possible permutations of this list. </p><p>If you write out all of these 24 possible permutations, you will find that only <code>5</code> satisfy the above requirement:</p><p><code>[1,2,3,4]</code> - no element changes index.</p><p><code>[2,1,3,4]</code> - elements 1&amp;2 change indices by +1 and -1 respectively.</p><p><code>[1,3,2,4]</code> - elements 2&amp;3 change indices by +1 and -1 respectively.</p><p><code>[1,2,4,3]</code> - elements 3&amp;4 change indices by +1 and -1 respectively.</p><p><code>[2,1,4,3]</code> - elements 1&amp;2 change indices by +1 and -1 respectively <strong>and</strong> elements 3&amp;4 change indices by +1 and -1 respectively.</p><p>In all of the <code>5</code> above permutations, the elements' indices have indeed changed by at most 1.</p><p>So for the input <code>n = 4</code> you should return the answer <code>5</code>.</p><p><strong>Explanation of an INVALID permutation for n = 4</strong></p><p>To be clear, let's consider another permutation which <strong>does not</strong> satisfy the kata's requirement, and therefore should not be included in your total:</p><p><code>[3,4,2,1]</code> - element 1 has changed index by +3, element 2 by +1, element 3 by -2, element 4 by -2.</p><p>The above permutation is therefore <strong>not</strong> allowed, since at least one element has changed index by <strong>more than</strong> 1.</p>

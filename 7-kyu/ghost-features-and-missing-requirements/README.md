<h2><a href=https://www.codewars.com/kata/69f195446b9845e840e44eda/train/csharp target="_blank">Ghost Features & Missing Requirements</a></h2><h3>7 kyu</h3><h3 id="the-educational-challenge">The Educational Challenge</h3><p>The QA team is complaining that they haven't received any formal requirements for the new <code>RefundService</code>. The developers argued, <em>"The code documents itself! Just read the code!"</em> </p><p>However, QA evaluated the codebase and proved that <strong>undocumented requirements inevitably create Technical Debt.</strong> Because there was no official documentation, the developers were forced to invent their own rules and assumptions while coding. This resulted in a tangled mess of "Ghost Features" (unwanted business rules) and rigid architecture that cannot be tested.</p><p>Management finally stepped in and provided the <strong>ONLY THREE</strong> official business requirements for refunds:</p><ol><li>Standard customers can get a refund within <strong>30 days</strong> of purchase.</li><li>VIP customers can get a refund within <strong>60 days</strong> of purchase.</li><li>Any request beyond those limits must be rejected.</li></ol><h3 id="your-task">Your Task</h3><p>Refactor the <code>RefundService</code> to enforce the official requirements and eliminate the garbage left behind by the lack of documentation.</p><p><strong>1. Pay off the Technical Debt (Make it Testable)</strong>Because QA had no documentation, they couldn't write automated tests. Because there were no automated tests, the developers carelessly hardcoded <code>DateTime.Now</code> directly into the logic! </p><ul><li><strong>Fix:</strong> Update the <code>RefundService</code> constructor to accept the provided <code>IDateTimeProvider</code>. Replace all instances of <code>DateTime.Now</code> with the injected provider so QA can finally write time-travel tests.</li></ul><p><strong>2. Exorcise the Ghost Features</strong>Because there were no official rules, the developers invented two undocumented restrictions. Delete them!</p><ul><li><strong>The Dev Hack:</strong> Emails containing <code>+test</code> bypass all rules. (A developer left this in so they wouldn't have to use real credit cards while testing).</li><li><strong>The Zombie Feature:</strong> Refunds are rejected on weekends. (A developer vaguely remembered Management mentioning this two years ago, so they just built it in).</li></ul><p><strong>3. Solve the Logic Puzzle</strong>Without a clear spec, the original developer used a nested <code>if/else</code> nightmare. Because of the order of operations, VIPs are currently being rejected at 31 days! Untangle the spaghetti code so VIPs actually get their 60 days.</p>

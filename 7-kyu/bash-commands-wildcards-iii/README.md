<h2><a href=https://www.codewars.com/kata/592c4159ee0ed543690000d5/train/c target="_blank">BASH commands: Wildcards III</a></h2><h3>7 kyu</h3><p>In BASH, when working with files, you can use the simple, yet very powerful feature, called the wildcards.</p><p>The most basic element of the BASH wildcards we will start with today, is the question mark <code>?</code> wildcard.</p><p>If you're familiar with regular expressions, it's very similar to the Regex's <code>.</code> behavior.</p><p>It works as follows. Assume you have a directory with the file names, as follows:</p><pre><code>- img00.jpg- img01.jpg- img010.jpg- imgAAA.jpg- imgAAB.jpg</code></pre><p>Then, <code>img0?.jpg</code>, will match the files <code>img00.jpg</code>, <code>img01.jpg</code>, <code>img010.jpg</code>. And <code>img???.jpg</code> will match <code>img010.jpg</code>, <code>imgAAA.jpg</code> and <code>imgAAB.jpg</code>.</p><p>In other words, <code>?</code> matches any character as long as there's any character in this given position. So <code>img00.jpg???????</code> will not match any files, neither will <code>img01??????</code>.</p><p>The task for this challenge is, given a string <code>pattern</code>, which may or may not have the <code>?</code> wildcard in it, and a NULL-pointer-terminated array (please, see below for details on NULL-pointer-terminated arrays) of files in the given directory as strings <code>filenames</code>, return a NULL-pointer-terminated dynamically-allocated array of the files that the string <code>pattern</code> matches.</p><p>If you have any questions regarding this problem's specification, please feel free to ask away in the Discussion section.</p><p>P.S.</p><p>A NULL-pointer-terminated dynamically-allocated array is an array, terminated by a NULL-pointer. For a better perspective, please consider this NULL-pointer-terminated array on stack:</p><pre><code>const char *names[] = {    "Dennis", "Ken", "Gary", "Brian", "Linus", "Bill",     NULL };</code></pre><p>Same applies to the dynamically-allocated array.Note that the elements themselves need not be allocated, and will not be freed by the tests. The array itself will be freed.</p><p>An empty array, terminated with a NULL pointer would look like this:</p><pre><code>const char *empty[] = { NULL };</code></pre><p>We need this to simplify traversal and avoid namespace pollution (and, perhaps, extra confusion) with additional variable definitions and pointer passing to denote a given array's size.</p>

<h2><a href=https://www.codewars.com/kata/6a3e71c30deee590ca66d415/train/java target="_blank">Java 21: Record pattterns and instanceof for switch</a></h2><h3>7 kyu</h3><p><a href="https://openjdk.org/projects/jdk/21/" data-turbolinks="false" target="_blank">Java 21</a> added the new features</p><ul><li><a href="https://openjdk.org/jeps/441" data-turbolinks="false" target="_blank">Pattern Matching for <code>switch</code> (JEP 441)</a> and</li><li><a href="https://openjdk.org/jeps/440" data-turbolinks="false" target="_blank">Record Patterns (JEP 440)</a>.</li></ul><p>They help to write better readable code with data-oriented programming, avoiding long <code>if-else</code> chains with heavy <code>instanceof</code> checks and type casts like</p><pre><code class="language-java"><span class="cm-keyword">if</span> (<span class="cm-variable">obj</span> <span class="cm-keyword">instanceof</span> <span class="cm-variable">MyClass</span>) {    <span class="cm-variable">MyClass</span> <span class="cm-variable">x</span> <span class="cm-operator">=</span> (<span class="cm-variable">MyClass</span>) <span class="cm-variable">obj</span>;    ...} <span class="cm-keyword">else</span> <span class="cm-keyword">if</span> (<span class="cm-variable">obj</span> <span class="cm-keyword">instanceof</span> <span class="cm-variable">MyRecord</span>) {    <span class="cm-variable">MyRecord</span> <span class="cm-variable">r</span> <span class="cm-operator">=</span> (<span class="cm-variable">MyRecord</span>) <span class="cm-variable">obj</span>;    <span class="cm-type">int</span> <span class="cm-variable">p1</span> <span class="cm-operator">=</span> <span class="cm-variable">r</span>.<span class="cm-variable">parameter1</span>();    <span class="cm-type">long</span> <span class="cm-variable">p2</span> <span class="cm-operator">=</span> <span class="cm-variable">r</span>.<span class="cm-variable">parameter2</span>();    ...}</code></pre><p>and replace it by</p><pre><code class="language-java"><span class="cm-keyword">switch</span>(<span class="cm-variable">obj</span>) {    <span class="cm-keyword">case</span> <span class="cm-variable">MyClass</span> <span class="cm-variable">x</span> <span class="cm-operator">-&gt;</span> ...    <span class="cm-keyword">case</span> <span class="cm-variable">MyRecord</span>(<span class="cm-type">int</span> <span class="cm-variable">p1</span>, <span class="cm-type">long</span> <span class="cm-variable">p2</span>) <span class="cm-operator">-&gt;</span> ...    ...}</code></pre><p>which is far more readable, isn't it?</p><h1 id="task">Task</h1><p>You are given the following record definitions in preloaded</p><pre><code>record Point(int x, int y) {}record Rectangle(int width, int height) {}record Circle(int radius) {}record CenteredCircle(Point center, int radius) {}</code></pre><p>and an implemented function <code>describeShape</code>, heavily using the above mentioned <code>instanceof</code>/cast/fieldaccess pattern and you should rewrite it using the mentioned new Java features.</p><h1 id="output-and-tests">Output and Tests</h1><p>The outputs of the functions should look like</p><pre><code>null --&gt; "null"new Point(0, 0) --&gt; "Point(0,0)"new Rectangle(10, 1) --&gt; "Rectangle 10x1"new Circle(1) --&gt;"Circle r=1"new CenteredCircle(new Point(1, 2), 3) --&gt; "CenteredCircle((1,2), r=3)"other object type --&gt; "unknown"</code></pre><p>To keep you terse, your code is only allowed to contain at most 7 semicolons (<code>;</code>).</p><p>The tests check that you are using a <code>switch</code> expression or statement and record component accessors or destructuring instead of field access.</p>

<h2><a href=https://www.codewars.com/kata/592dd97fdc403b877e0000c7/train/c target="_blank">BASH commands: Wildcards I</a></h2><h3>7 kyu</h3><p>In BASH there's a simple, yet a powerful feature, called the wildcards. In this first iteration of the problem, we will tackle the most basic of all wildcards in BASH, - the question mark <code>?</code> wildcard.</p><p>So when does this all get used? Whenever searching for a file, sometimes you might be interested in matching a set of files based on their name, for example given a list of files:</p><pre><code>- aa.jpg- ab.jpg- ac.jpg- za.jpg- zb.jpg</code></pre><p>We might be interested in selecting all the files starting with an <code>a</code> character, such as: <code>aa.jpg</code>, <code>ab.jpg</code> and <code>ac.jpg</code>. For this particular case, we would use: <code>a?.jpg</code>, to get the desired result.</p><p>The question mark wildcard <code>?</code> is very similar in its behavior to the <code>.</code> in Regexp, that is, it matches any character as long as its there. For example, <code>.?</code> will match <code>.a</code> and <code>._</code>, but not <code>a</code> and not <code>.</code>. This effectively implies that the pattern length should equal the length of the matched string.</p><p>The question mark wildcard <code>?</code> can be used in a pattern as many times as necessary. For example, <code>?b?.gif</code> or <code>???.elf</code> or even <code>????</code>.</p><p>Given a string <code>pattern</code> representing the pattern that may or may not contain wildcards, and a string <code>filename</code>, return a truthy value if the given pattern matches the filename, or a falsy value, if it doesn't.</p><p>If you have any questions and or suggestions regarding the task, please feel free to write in the discussions. Have fun!</p>
